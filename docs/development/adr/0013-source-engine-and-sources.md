# Separate Source behavior from installed Source ownership

Job Radar separates reusable Source behavior from installed application state in two Tauri-free crates. `source-engine` owns the `definition`, `detection`, and `execution` Modules: Source Behavior Language schemas and compilation, bounded Profile Detection, and bounded/cancellable Discovery and lazy Detail. `sources` owns admitted Built-in and Custom Source Profiles, persisted Sources, lifecycle-safe mutations, installed Profile Detection, Source Live Checks, reports, freshness, and admission. Desktop depends on `sources`, `sources` depends on `source-engine`, and `search-resolution` deliberately consumes `source-engine::execution`; reverse dependencies are prohibited.

Reqwest and managed Chromium remain Desktop Adapters for engine HTTP and Browser interfaces. The engine excludes native networking, Chromium, Tauri, filesystem and SQLite ownership, Search Request matching, lifecycle policy, and application composition. Candidate Resolution remains in `search-resolution`; there is no compatibility facade or speculative storage, shared-model, catalog, application, language, or runtime crate family.

An installed-state operation uses one immutable, operation-local Snapshot so each prepared Source is tied to the exact admitted Source Profile material used to compile it. Invalid Custom Source Profiles remain inspectable with Structured Diagnostics but are quarantined from productive lookup and Detection; invalid Built-in Source Profiles fail initialization. Loading is bounded to 256 Custom Source Profiles at 1 MiB each and 32 MiB aggregate, with 100 Diagnostics per document and 4,096 total, and 4,096 Custom Sources at 256 KiB each and 64 MiB aggregate, with 100 Diagnostics per document and 16,384 total.

Snapshots remain operation-local rather than cached or watcher-backed so manually managed app-data JSON files are observed on the next operation without a speculative invalidation protocol. Source/Profile documents therefore remain canonical filesystem JSON, while Source Behavior Language and Source Profile schemas live once under `source-engine` and persisted Source and Check Report schemas live once under `sources`.
